# My Roster Web v0.8

무료 정적 웹앱 업데이트. HTML, CSS, JavaScript만 사용. 빌드 및 npm 설치 불필요.

## GitHub Pages
ZIP 압축을 풀고 내부의 파일을 저장소 최상위에 업로드합니다. Settings → Pages → Deploy from a branch → main → /(root) → Save. 생성된 사이트를 iPhone Safari에서 열어 홈 화면에 추가합니다.

실제 근무표, 개인 사번, 동료 이름, 백업 파일은 공개 GitHub 저장소에 업로드하지 마세요. 앱에서 입력한 정보는 브라우저 localStorage에 저장합니다. 백업 JSON은 암호화하지 않습니다. 데이터 삭제나 브라우저 저장공간 정리에 대비해 수동 백업을 자주 생성하세요. 파일 공유를 지원하는 브라우저에서는 공유 메뉴로, 그렇지 않으면 다운로드 후 파일 앱에서 AirDrop 등을 이용합니다.

## 구현
월간 캘린더, 빠른 입력, 코드 시간 버전 및 숨김, 개인 일정 시작시간 선택, 추가 근무, 엑셀/CSV 붙여넣기 및 REV 변경 이력, 같은 날짜 교환 검색 및 양쪽 검증, 월 경계 검사, 월/연 근무시간 및 연차, 구간별 RAMP 시간 및 UTC/KST, BLOCK TIME, ORDER/ADD 기록용 계산, 공항 거리 추정, 백업/복원, 근무표 ICS 내보내기, PWA 매니페스트 및 오프라인 캐시.

## 한계 및 검증
세계지도, 기상/백그라운드 예약 알림, 위젯, Face ID, 자동 동기화, 서로 다른 날짜 교환, 공통 휴무 검색, 반차 사용 집계는 미구현. Apple Calendar는 파일 내보내기만 구현. 웹앱 전용 백업이며 기존 Swift JSON과 직접 호환되지 않습니다. 기본 출발 공항 TAE는 설정 가능. 근무시간은 KST 자정 분할, 휴게 미차감, 월요일 시작 주 기준의 참고용 계산. 근무표 자료 부족 시 정확한 수당 판단 불가. 연료는 사용자가 제시한 공식의 개인 기록/검산용이며 운항 적합성 판단 불가. 홀수 ORDER 잔여 1은 MAIN 2. CTR 상한 및 허용 불균형은 미설정.

v0.2 검증: Node 신규/회귀 테스트 23개 통과. JavaScript 문법 검사 통과. Chromium 인라인 DOM 테스트에서 빠른 입력/실행 취소/건너뛰기/월말 정지, 사진 선택/수동 검토/기존 기록 보존, 모의 OCR 결과의 사번 일치/REV/저장 통과. 실제 Tesseract 엔진과 한국어 모델 다운로드, 실제 이미지 OCR 정확도, 실제 브라우저 저장 지속성, 서비스 워커 오프라인 및 iPhone Safari는 미검증. GitHub Pages 배포 미실행.

## v0.2 업데이트
기존 주소와 localStorage 키(myroster.web.v1)를 유지합니다. 기존 기록을 먼저 설정에서 백업한 뒤 기존 MyRoster-Web 저장소의 루트에 ZIP 내부 파일 13개를 덮어쓰세요. ZIP 자체를 올리지 마세요. GitHub Pages 배포 완료 후 기존 홈 화면 앱을 종료하고 다시 열어주세요. 설정 하단에 My Roster Web 0.2가 보이는지 확인하세요. 이전 캐시가 보이면 인터넷 연결 상태에서 앱을 다시 열어주세요. 앱 또는 브라우저 데이터를 삭제하지 마세요.

### 빠른 입력
날짜를 한 번 선택하고 근무 코드 버튼만 연속 터치하면 다음 날짜로 이동합니다. 월말에는 멈춥니다. 이전 날짜, 건너뛰기(기존 기록 유지), 실행 취소, 설정의 자동 이동 OFF(기존 칠하기 방식)를 지원합니다.

### 사진 OCR (시험 기능)
캘린더 → 근무표 가져오기 → 사진으로 등록. 사진을 선택하고 월과 직원 행 수를 확인합니다. 기존 사진 양식과 동일하면 예시 양식 영역을 사용하거나, 첫 직원 이름 칸 왼쪽 위 → 첫 직원 1일 칸 왼쪽 위 → 마지막 직원 마지막 날짜 칸 오른쪽 아래를 지정합니다. 필요하면 사진을 확대하세요. 사진은 정면에서 촬영한 화면 또는 선명한 캡처가 좋습니다. 직원 표의 오른쪽 연차 합계와 아래 인원 집계는 포함하지 마세요.
사진 문자 인식은 Tesseract.js v5.1.1을 jsDelivr에서 필요시 로드하며 한국어/영어 모델과 엔진도 다운로드합니다. 이미지 전송 코드는 없고 사진 인식은 브라우저 안에서 처리하지만 외부 라이브러리 다운로드는 네트워크가 필요하며 외부 코드의 동작까지 독립적으로 검증하지 않았습니다. 실제 엔진이 캐시되어 있더라도 오프라인 OCR은 보장하지 않습니다. 사진 원본은 저장하거나 공개 저장소에 포함하지 않습니다.
사번이 정확히 하나 일치하면 본인 행을 선택하고, 그렇지 않으면 직접 지정합니다. 동료 사번은 저장하지 않습니다. OCR에서 월을 인식한 경우 선택 월과 비교하고 다르면 중단합니다. REV는 인식된 경우 미리 채웁니다. 모든 포함 행과 셀을 검토하고 변경사항 미리보기 후 저장합니다. 공란은 기존 근무 유지, 명시적 삭제는 '-' 입력. 미등록 코드는 사진과 대조 후 별도 동의로 기록할 수 있으며 시간 통계는 미정 처리합니다. 기존 개인 일정, 추가 근무, 탑승 기록은 유지합니다. 스캔 실패 시 사진을 보며 수동 표 입력 또는 기존 엑셀 붙여넣기를 이용하세요.


## v0.3 — 원터치 수동 백업
기존 MyRoster-Web 주소와 localStorage 키(myroster.web.v1)를 그대로 유지합니다. 업데이트 전 기존 앱에서 백업을 만들어 실제 파일이 저장되었는지 확인하세요. 이번 ZIP 내부 파일 14개를 기존 GitHub 저장소 루트에 덮어쓰고 Commit changes. GitHub Pages 배포 완료 후 온라인 상태에서 앱을 닫았다 다시 실행하여 설정 하단 My Roster Web 0.3을 확인합니다. 구버전이면 앱을 다시 실행하거나 Safari에서 같은 주소를 다시 엽니다. 앱 삭제나 웹사이트 데이터 삭제는 하지 마세요.

- 첫 기록 후 백업 안내, 마지막 백업 후 30일 기본 주기 (7/14/30/60일 선택), 새 월 근무표 가져온 뒤 안내, REV 변경 후 안내 선택.
- 캘린더 상단 안내에서 바로 백업. 내일 다시 안내, 이번 달 건너뛰기, 안내 끄기 가능. 앱을 열었을 때 평가하며 종료 중 푸시 알림은 아님.
- 기본 백업 범위는 내 기록만(동료와 REV 이력 제외). 설정 → 백업 안내·범위 설정에서 포함할 수 있음. 선택한 범위와 마지막 백업 이후 변경 여부를 표시.
- 지원 환경에서는 JSON 파일을 iOS 공유 메뉴에 전달. 파일 공유 불가 시 다운로드, 공유 오류 시 다운로드 버튼 제공. 공유 취소 시 마지막 백업 날짜 유지. 실제 파일 저장 여부는 앱에서 확인할 수 없으므로 표시 날짜는 생성·전달 요청 시점이며 파일 앱에서 확인 필요.
- 파일명에 KST 날짜와 시각 포함. 자동 업로드/동기화 없음. 백업 파일은 평문 JSON이며 공개 저장소에 올리지 말 것.
- v0.3 검증: Node 기존 23개 및 추가 백업 로직 15개(합계 38개) 통과. Chromium 인라인 UI 테스트 6개 시나리오(모의 localStorage, 공유 및 다운로드 호출 대체) 통과: 구버전 상태 읽기, 미루기/건너뛰기, 취소, 원터치 공유 자료, 다운로드 자료·범위, JSON 파일 복원. 실제 iOS 공유, AirDrop, 실제 저장 지속성, 서비스 워커와 오프라인 실행은 미검증(로컬 HTTP 차단). 실제 OCR은 여전히 미검증 시험 기능. GitHub Pages 배포 및 아이폰 확인 필요.

## v0.4 — 한 줄 사진 인식 개선
- 기본 사진 인식 모드는 내 근무표만. 이름/사번 없이 1일부터 말일까지의 근무 칸 모서리 두 점 선택 또는 근무 칸만 자른 이미지 전체 사용. 전체 직원 모드는 이전 기능 유지.
- 원본 픽셀 기준 한 줄 영역 허용, 2배/4배 확대, 날짜별 칸을 6열 격자로 재배치 및 대비 개선, 영문 OCR. 날짜별 원본과 결과를 함께 보여주며 저장 전 확인 필수. 월·날짜 칸 개수가 정확해야 합니다. 사진에 날짜 헤더나 이름이 있으면 영역에서 제외하세요.
- 개인 사진의 REV 미입력은 개인 사진으로 기록. 데이터 저장 키 및 배포 주소 유지, 서비스 워커 캐시 버전 변경.
- 실제 OCR 엔진 및 아이폰 테스트 미실시. 사진이 흐리거나 원본 픽셀이 부족하면 정확도 보장 불가.

검증: Node 한 줄 영역 및 28~31일 칸 매핑 테스트 통과. Chromium 인라인 환경의 합성 18px 높이 한 줄 사진과 모의 OCR 결과를 이용한 모드 전환·날짜별 검토·저장 테스트 통과. 실제 브라우저 저장은 대체 구현으로 검사했으며 실제 OCR 정확도와 Safari는 미검증입니다.

## v0.5 — 교육 상세
E 근무 날짜 선택 → 교육 정보. 날짜별 교육명과 선택적 시작/종료시간(KST)을 등록합니다. 시간은 두 항목 모두 입력하거나 둘 다 비우며, 종료가 시작보다 이르면 다음 날로 해석합니다. E 근무 코드의 기본시간보다 우선하고, 근무 통계·최소휴식 검증·개인 일정 충돌·ICS에 반영합니다. 날짜별 1개 교육 상세를 지원합니다. 빠른 근무 입력은 그대로이며, 교육 정보는 나중에 입력합니다. 근무표 재등록·백업·복원 시 교육 정보 보존. E가 아닌 날에는 교육 기록을 집계하지 않으며 다시 E로 변경하면 기존 정보가 표시됩니다. 기존 주소 및 저장 키 유지. 설정에서 버전 0.5 확인. 실제 iPhone 및 OCR 검증은 이전과 동일하게 필요합니다.

검증: 기존 38개 + 신규 교육 로직 13개 = 51개 Node 테스트 통과. 모든 JS 문법 검사 통과. Chromium 인라인 UI(모의 localStorage 및 ICS 다운로드)에서 구버전 호환, E 빠른 입력, 교육명/시간 저장 및 표시, 통계, 수정, ICS 내보내기, 교육 정보만 삭제를 확인했습니다. 실제 iPhone Safari, 영구 저장, 오프라인 캐시 및 GitHub Pages 배포는 미검증입니다.

## v0.6 — 월별 전체지우기
캘린더에서 삭제할 월을 선택 → 달력 아래 전체지우기 → 삭제 건수와 범위 확인 → 동의 체크 → 확인 · 삭제. 확인 전에는 자료를 변경하지 않습니다. 기본은 내 근무표 및 해당 월의 날짜별 교육 상세만 삭제하며, 동료 근무표는 별도의 체크박스로 포함할 수 있습니다. 범위 변경 시 동의 체크가 초기화됩니다. 빈 범위는 삭제 불가. 다른 달, 개인 일정, 추가 근무, 탑승·연료, 휴일, 연차 부여 설정 및 기존 REV 이력은 유지합니다. 삭제한 V 근무는 연차 집계에서 제외되고 근무 경고 및 통계는 새 자료로 계산합니다. 기존 REV 이력은 삭제되지 않으며 근무표 삭제 내역도 REV 전체지우기로 기록됩니다. 개인정보 완전 삭제 기능은 아닙니다. 저장 실패 시 변경 전 상태로 돌아가며, 성공 후에는 빠른 입력의 실행 취소로 복구할 수 없으므로 먼저 백업하세요.
기존 주소 및 저장 키 유지. 14개 파일을 기존 저장소에 덮어쓰고 배포 후 설정에서 0.6 확인. Node 회귀 51개 및 신규 삭제 로직 11개 통과. Chromium 인라인 UI(모의 localStorage)에서 확인/취소, 동료 포함 변경 시 재동의, 저장 실패 복구, 내 근무만 삭제, 빈 범위 차단, 동료 포함 삭제, 이력 기록 및 교육 UI 회귀 확인. 실제 iPhone과 서비스 워커 배포는 미검증.

## v0.7 — OCR 코드 보정 및 정밀 인식
C 코드 숫자 부분의 O/I/L 등 혼동을 등록된 근무 코드에 한해 보정. 등록 코드 원문 우선, 미등록 값은 임의 추정하지 않음. 보정된 칸은 노란색, 한 줄 검토에 원문 및 다른 재인식 결과 표시. 각 칸 별 대비 정규화, 색상 글씨 보정, 선택 영역 날짜 경계선 및 정밀 재인식(한 줄 최대 31칸, 전체 최대 40칸, 선택 해제 가능). 기존 저장 키 유지. 실제 OCR 엔진 및 iPhone 인식률 검증 필요.

검증: 기존 Node 테스트 62개 및 신규 OCR 보정/재인식 선택 14개 통과. Chromium 인라인 모의 OCR에서 CIO → C10 보정, 경고 및 원문 표시, 한 줄 검토와 저장 통과. 실제 OCR 정확도는 측정하지 못함. 업데이트 전 백업, 14개 파일을 기존 저장소 루트에 덮어쓰고 설정 하단 0.7 확인.


## v0.8 — 다중 교육 및 DH/DUTY 탑승 기록
- 기존 v0.7 OCR 개선 포함. 기존 URL, localStorage 키 및 백업 형식 version 1 유지. 업데이트 전에 백업을 저장하고 기존 저장소 루트에 14개 파일을 덮어씁니다. 앱을 삭제하지 마세요.
- E 날짜에 여러 교육을 추가·개별 수정·삭제할 수 있습니다. 교육명, 선택 시작/종료(KST), 메모. 기존 단일 객체는 읽을 때 한 건으로 처리하며 편집 시 배열로 저장합니다. 시간 중복은 경고하고 한 번만 집계, 공백 및 미입력 시간은 합산하지 않습니다. 달력에는 첫 교육명 외 N건 표시. ICS도 개별 교육으로 내보냅니다.
- 탑승은 첫 구간 DH만 생성. 복편(DUTY)은 직접 추가, 삭제 및 날짜 변경. 출발일은 KST 날짜이며 RAMP OUT을 입력하면 해당 시각의 KST 날짜로 자동 맞춥니다. 출발일을 수동 변경하면 이미 입력한 해당 구간 RAMP 시간도 같은 날짜 차이만큼 이동합니다. UTC/KST 전환 시 실제 시점 유지.
- 캘린더에는 DH 출발일의 공항 코드만 반영. DUTY가 익일이어도 그날 OFF 등 기존 근무를 변경하지 않습니다. DH 날짜 변경으로 기존 일정을 이동할 때 확인합니다. 복편에는 ORDER/ADD 입력, DH에는 입력란 없음. 이전 기록의 첫 구간은 DH, 나머지는 DUTY로 표시하며 기존 DH 연료 값은 삭제하지 않습니다. 기존 탑승 기록의 근무표 날짜는 일괄 변경하지 않으며, 상세를 수정할 때 DH 실제 출발일과 차이가 있으면 확인 후 반영합니다.
- DH/DUTY 구간 수 및 BLOCK TIME을 따로 집계(월 구분은 DH 근무일 기준). 항공편 시간은 일반 근로시간, 야간/연장/휴일 계산에 넣지 않습니다. 별도 입력한 추가 근무는 계속 집계합니다. 탑승일은 근무표상 연속근무일에 포함. 탑승의 실제 전체 근무·휴식 시간은 추정하지 않습니다. 연료는 기존 개인 기록/검산용 제한 유지.
- 검증: 기존 76개 로직 테스트 재실행 및 신규 13개 통과(총 89개), JavaScript 문법 검사 통과. Chromium에서 모의 localStorage로 다중 교육 등록/편집/삭제, 복편 선택 추가, DUTY 날짜 변경, UTC/KST 변환, DH 연료 입력란 미표시, 기존 OFF 유지, 탑승 통계 표시 확인. 실제 iPhone Safari, OCR 엔진 및 오프라인 캐시 작동은 미검증. GitHub Pages 배포는 사용자가 진행합니다.

## v0.9 비행지원
- 기존 v0.8 파일 전체를 동일 GitHub Pages 경로에 덮어쓰기 (support.js 신규 포함).
- 캘린더 날짜 선택 시 비행지원 목록; 닫으면 기존 선택일 상세 및 빠른 근무 입력 사용 가능. 페인트 입력 모드에서는 기존 동작 유지.
- DST 이력 추가, 항공기별 DST 연결, 항공사/기번 접두어 기억, ETA/STD HHMM KST, DEFER 상세 팝업, 체크리스트 라이브러리.
- 입력란 변경 시 자동 저장, DEFER는 팝업 저장 버튼 사용. 체크리스트는 추가/선택 시 저장.
- 비행지원 저장 키는 myroster.flightSupport.v1, 기존 스케줄 키는 변경 없음. 백업/복원 별도. JSON은 암호화되지 않으므로 회사 정책 준수 및 비공개 보관.
- UTC 시계는 기기 시각 사용. MEL/NEF는 사용자 지정 일수 단순 가산 참고용, 승인된 정비 절차 대체 불가. 연료 배분도 참고용.
- 날짜 변환 및 날짜 가산 단위 테스트 6개 통과. 브라우저 실행은 환경 정책에 의해 차단되어 실기기 검증 필요.
